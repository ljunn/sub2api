# 上游站点与价格调度

后台「站点管理」支持 Sub2API、New API 和空凡。填写站点首页地址和后台登录凭据，保存后获取可用分组、模型和价格。登录凭据使用 AES-256-GCM 加密，密钥从持久化的 JWT 安装密钥通过带独立用途标识的 HMAC-SHA256 派生，不依赖未配置时会随机变化的 TOTP 密钥。列表与错误响应不返回密码、Token 或上游 Key。支持密码、Access Token、Refresh Token；需要验证码或二次验证的站点先在上游完成登录，再提供令牌。

备份时保留安装配置中的 JWT 密钥；预览与生产必须使用同一个已持久化的 JWT 密钥。轮换此密钥前需安排站点凭据迁移，直接更换会使旧站点凭据无法解密。

绑定选择「上游分组 + 模型 → 本地分组 + 模型别名」。托管账号名称统一为 `【站点】上游模型（上游站点分组）`，括号中不是本地分组；新建及同步时更新托管名称，历史非托管账号不变。采购单价上限自动读取本地分组、模型售价计算，不接受手工数值；绑定页面只配置档位启停。每个绑定自动创建一个独立上游 Key 和本地 API Key 账号。上游 Key 用绑定 UUID 命名，创建超时后重试先查找已有 Key。Sub2API Key 固定分组；New API Key 同时限制模型并关闭跨分组重试。本地托管账号的凭据、分组和模型映射由站点管理维护。

一个模型绑定对应一个账号，1K、2K、4K 是该账号内的独立价格档位。超价只排除对应档位；请求分辨率未知或为自动时要求所有分辨率均符合上限。上游价格下降后下一次成功同步自动恢复；本地调价由每次调度和实际发送前重新读取，自动暂停或恢复，手工暂停账号不会被价格恢复覆盖。

## 托管账号并发

用户于 2026-09-21 要求读取上游真实并发限制，未公开限制时采用本地默认 1000，取消新建托管账号写死为 1 的行为。Sub2API 读取登录账号 `/api/v1/auth/me` 的 `concurrency`；空凡读取 `/api/v1/user/profile` 的 `effective_max_concurrency`，缺失时回退 `max_concurrency`；New API 读取 `/api/user/self` 中可选的同类字段。有效并发优先于未应用 VIP 等覆盖规则的原始配置，RPM 不作为并发数。

站点保存已核验的并发值、字段来源和读取时间。新建绑定立即使用该值，模型/价格同步同时更新该站点已有托管账号的并发；缺失或零值采用 1000，接口失败或无效数值保留已知限制，不把读取失败当成无限制。历史独立账号和管理员手动调度开关不变。多个绑定使用同一上游登录账号，其上游用户总并发仍由对方统一限制，不能把每个绑定的数值相加当作新的上游额度。

2026-09-21 实查：非奇异账号并发 5000、飞羽 500、空凡有效并发 1000、supergpt 150；这些站点可用分组没有另行公开并发上限。参分的账号、可用分组和公开状态接口没有公开并发上限，因此按用户要求使用 1000；此默认值不代表已证明上游无限并发。

## 紧凑展示与实际调度状态

站点总览按「全部站点 / 有新模型 / 余额不足 / 连接异常」显示站点数量，支持点击筛选和按名称、地址搜索。可滚动的紧凑列表同时显示各站点的新模型数、折算后的 USD 余额、连接状态和绑定数量，不再靠横向滑动逐个站点找异常。同一站点可同时出现在新模型和低余额筛选中；低余额读取已保存的 USD 系统提醒阈值，不受邮件开关影响。失败或超过 10 分钟的余额标记为待更新，保留最后已知的低余额提示，不把过期金额当作正常。停用站点不计入低余额、连接异常数量。

主页面只保留站点总览，不默认展开第一个站点。站点行整行可点击打开宽弹窗，包括地址、状态、绑定数量和空白区域，也支持键盘 Enter / 空格。余额、绑定表、上游模型及价格变化都在弹窗中；关闭后返回原列表，刷新不会重新弹出。编辑、绑定、删除确认与详情互斥展示，取消或完成后返回原站点，避免叠层弹窗和 Escape 同时关闭多层。带 `?site=<ID>` 的已有入口仍直接打开对应站点。新增模型按钮直接进入该站点模型列表，不被行点击覆盖。列表刷新与先前站点的余额查询、同步结果只更新数据，不覆盖用户后来选中的站点；保存新站点后自动选中它，但不会抢回保存期间用户已经切换的选择。回归测试覆盖这些切换与异步返回场景。

### 新增模型与已读

- 按「上游分组 ID + 模型名」识别可绑定项目。首次成功同步建立基准，不把整个初始目录提示为新增；升级前已有的成功目录沿用为基准。后续成功同步才识别新增，普通调价不会重新提醒；模型下架后重新出现属于一次新的发现。失败同步不更新基准。
- 点击站点的「N 个新模型」直接打开新增模型列表；也可从「上游模型」页查看全部模型。新增项目排在前面，价格并排显示，绑定仍需管理员主动选择本地分组并保存，不自动创建本地托管账号；缺少分组读取 Key 时会自动创建并复用。
- 仅在浏览器前台、模型行至少一半进入可见区域时，向 `POST /api/v1/admin/upstream-sites/:id/models/read` 提交实际看到的 `discovery_ids`。未进入模型页、未滚动看到、搜索排除或后台标签页中的项目不会被清除。当前查看中的新增项目保留在列表内，便于继续决定是否绑定；总览的未读计数即时减少。
- 已读记录按当前管理员和站点持久化到 PostgreSQL `settings` 的 `upstream_site_models_read:<管理员 ID>:<站点 ID>`。换浏览器、刷新或重启后继续生效，不影响其他管理员。只确认明确的发现 ID，同步期间刚到达的其他模型不会被顺带清除；多标签页合并记录，前端忽略旧轮询响应对已读状态的覆盖。保存失败保留提示并提供重试。
- 目录基准独立于价格缓存保存，修改密码或积分换算不会让同一模型重复提醒；更换站点身份则重建基准。模型已读接口只保存通知状态，不修改站点绑定、账号状态或调度策略。低余额提示持续到余额恢复，不因查看模型而消失。
- 新模型检测复用每 5 分钟的模型/价格同步。用户已授权 6556 在独立测试分组中正常调度，预览也自动更新模型目录和价格，并保留「立即同步」入口；自动余额扫描继续运行。

站点绑定改成每个模型一行的表格；1K、2K、4K 采购价及是否可调度（✓/×）同一行展示，悬浮查看本站售价、采购上限和阻断原因，完整配置仍在「定价 / 启停」。上游分组与本地分组分列，避免名称混淆。

账号管理通过 `site_scheduling` 返回实时评估结果，读取当前分组定价而非账号中保存的旧上限。站点托管账号显示「参与调度」「部分可调度」或「停止调度」，每档有超价、过期、未知、停用或等待上线原因，不再显示含糊的「按分组售价判断」。状态栏和调度栏使用相同结果；手动调度开关不再被展示成价格检查通过。

全部档位不符合时实际请求会被价格门禁排除，调度和每次向上游发送前均复查；某档不符合只停止该档。自动价格阻断不覆盖管理员手动开关，从而允许降价后自动恢复，手动停用仍保持停用。页面是普通分组价的当前判断，实际请求还检查用户专属倍率和运行时限流。没有给历史账号自动添加托管关系。

## 自动采购上限

本地分组设置新增「允许等价模型调度」，已有分组和新分组默认关闭。关闭时各有价计费分量的采购价必须严格低于本组自动采购上限，开启后可等于上限；超价、缺价、过期和手工停用仍阻断。免费辅助分量不妨碍已打折的有价分量，整个档位都为零则视作等价。页面和后端使用相同的浮点容差判断，命中显示「等价暂停」。配置按分组持久化，复制分组保留配置；调度与每次实际发送读取最新分组，开关变化不必等待上游同步，且不修改手工启停。

站点总览每行提供「打开站点 ↗」，在新标签页打开已保存的上游首页，不触发站点详情弹窗。

托管绑定的实际扣费也固定使用本地模型别名，不随上游模型改名或响应中的模型名改变。本站售价复用实际计费解析链（本地分组模型价卡 → 渠道模型价 → 目录/内置默认价），并计入分组倍率。图片使用分辨率定价及图片独立倍率，token 使用高峰和渠道分时倍率。开启分组利润保护时：`上限 = 本站售价 × (1 − 最低利润率 − 安全余量)`；关闭时上限等于售价，仍避免已知单价亏损。

页面显示普通用户的分组售价。请求调度还会读取用户专属倍率；图片独立倍率仍按现有计费规则处理。本地价卡修改后无须重新绑定或等待上游同步。若请求持有修改前的分组快照，使用新旧售价较低者比较。账号保存的上限仅用于展示，不作为实际发送的价格依据；无法读取本地价格时停止该绑定的调度。

上游图片为固定单价时展开成 1K / 2K / 4K，与本站三档分别比较。上游上下文采用最高采购价，本地上下文采用最低售价，避免未识别上下文档位造成亏损。无法覆盖的计费项目（例如没有对应本站单价的独立音频 token）暂停该档位；应在本站配置对应计费能力后接入。

## 同步与价格口径

- 后台每分钟检查到期任务，每次同步后安排 5 分钟后的下一次同步；页面支持「立即同步」。自动价格有效期 10 分钟，短暂同步失败保留未过期价格，过期后停止调度；管理员填写的手动采购价不受自动价格有效期影响。
- 价格包含上游个人/分组倍率。Sub2API 图片独立倍率、上下文阶梯、分时/高峰、最高推理倍率按已公开字段处理；上下文与分时价格采用最高单价作为保守上限。
- USD/次、USD/张、USD/百万 token 分开比较。输入、输出、缓存和其他公开成本分量分别从本地计费价格计算上限，未覆盖项目不视为免费。
- New API 支持固定按次价格、token 倍率，以及可安全归约的非负线性计费表达式（条件分支取各分量最高值）。复杂任务插件、非线性规则或不完整价格显示不可核价并暂停调度。额外服务档位（priority/fast/flex 等）尚未单独核价，托管账号不会承接这类请求。
- Sub2API 优先读取模型广场；`/api/v1/model-plaza` 返回 HTTP 404（包括明确关闭模型广场）时尝试 `/api/v1/public/model-pricing`，兼容飞羽等分支。公开价格也返回 404 时，继续使用登录后的 `/api/v1/groups/available`、`/api/v1/groups/rates`、`/api/v1/channels/available` 和各分组 Key 的 `/v1/models`（缺少时自动创建）。401、403、429、5xx、非 JSON 等异常仍明确报错，不当作接口缺失。模型广场不是接入前提，缺少模型列表的分组单独警告，不中断其他分组。模型改名或下架不会自动猜测替换关系，需要重新绑定到本地别名。
- 站点目录、绑定账号价格策略和调度缓存失效事件在一个 PostgreSQL 事务中发布。请求调度及每次实际发送（含重试）均检查价格；已付费结果的 GET 下载不受新涨价影响。
- 保留最近 100 条价格变化。解除绑定删除本地托管账号，上游 Key 保留；删除站点须先解除全部绑定。

五分钟轮询无法感知两次扫描之间的即时涨价；本功能依赖上游发布的价格，站点余额可手工配置 USD 换算倍率，空凡的积分采购价使用同一倍率，具体见 [UPSTREAM_SITE_BALANCE.md](UPSTREAM_SITE_BALANCE.md)。

## 飞羽公开价格兼容

飞羽（`https://www.hqjcw.com`）仍选择 Sub2API 格式，沿用已保存的登录、余额查询和分组 Key 流程。其模型价格来自公开价格接口，目录按 `groups` 与 `models[].group_id` 关联；同步另外读取当前账号的 `/api/v1/groups/available` 和 `/api/v1/groups/rates`，只列出当前账号可用的分组，不因公开可见就允许绑定。

公开价已包含分组计价：图片直接读取 `image_price_1k/2k/4k`，按次读取 `per_request_price`，token 单价由 USD/token 换算成 USD/百万 token。不能再次乘可用分组中被隐藏成 0 的倍率，也不应用仅用于人民币估算的充值比例。上下文阶梯取各分量最高公开单价。未公布价格、缺少图片档位、缺少输入/输出单价不当作免费；明确数值 0 与空值区分。若账号有个人专属费率，或启用未完整公开的高峰/分时价格，则显示不可核价并阻止调度，不能从公开价和隐藏倍率猜测成本。

2026-09-21 排查确认飞羽原有凭据有效，404 源于接口差异。公开目录为 11 个分组、38 个模型项目，但当前登录账号实际可访问 12 个分组；`GPT生图对接组`（ID 19）设置了 `public_pricing_visible=false`，仅取公开目录会漏掉它。

同步以登录后的可用分组为准补齐专属分组：查找该账号已有、启用且分组 ID 匹配的 API Key，用它读取 `/v1/models`，没有可用 Key 时自动创建一个读取 Key，随后复用；不跨分组借用模型清单。公开目录确认过计费类型的图片模型，读取该专属分组自己提供的 `image_price_1k/2k/4k` 最终单价；不能复制别组价格、乘隐藏的零倍率，也不从说明文字解析费用。当前对接组的 4 个图片模型三档字段均为 $0.04/张，其说明中的 $0.03 为不同信息，核价使用结构化字段。无法确认价格的模型标明原因并暂停调度；Key 自动创建失败时提示对应分组及失败原因，不影响其他分组同步。该账户合计应显示 12 个分组、42 个模型项目（分组与模型组合计数，含未公布价格的项目）。新增模型仍由管理员决定是否绑定，保存绑定时再创建该绑定独立的调用 Key。

## 无模型广场的登录接口回退（含 supergpt）

2026-09-21 实查 `https://supergpt.cc`：登录、余额、7 个可用分组均可读取；`/api/v1/model-plaza` 明确返回 HTTP 404、`Model plaza is not enabled`，公开设置 `model_plaza_enabled=false`；它也没有飞羽的公开价格接口。现有 Key 的模型列表仅提供名称，没有完整模型价格，部分分组的图片价格为空，说明文字不能当作自动调度成本。

模型广场关闭后仍然同步：先尝试公开价格，再读取账号可访问的分组、个人倍率、可用渠道模型价及已有 Key 的模型列表。同步不修改上游模型广场设置；缺少 Key 的可用分组自动创建读取 Key。可用渠道提供完整模型价时，按当前分组图片覆盖价、个人费率、图片独立倍率和高峰倍率计算；同一模型存在多个渠道时采用各成本分量最高价，任何候选渠道缺价或计费单位冲突都不能误判为可核价。不能绑定账号无权访问的分组。

实查 supergpt 的可用渠道接口返回空列表，最初只有 15、23 两个分组有可读 Key，读取到 5 个分组与模型组合；现已按用户要求对缺少 Key 的可用分组自动创建并复用读取 Key。分组 15 的结构化图片基础价为 1、倍率为 0.008，可显示 `$0.008/张` 的分组参考价；部分分组图片价为 null。模型名称只能确认图片能力，不能证明其实际按图片计费，也不能排除模型专属覆盖价，因此参考价会明确标注来源，并提供手动填写实际采购价的入口，不从说明文字猜单价、不用本站默认价格代替上游价格。

站点保持「已连接」，目录缺项通过 `warnings` 展示，模型缺价通过各模型原因展示。未知价格的模型也允许先配置绑定，但在实际采购成本确认前不参与托管调度；没有价格不等于免费。完整价格源恢复后重新同步会清除警告并恢复正常核价。

## 预览与发布

6556 仍复用生产 PostgreSQL、JWT、现有管理员及业务数据，Redis 保持独立 DB 14。用户于 2026-09-21 明确要求取消预览统一停用，通过新建分组隔离测试，因此预览服务设置 `UPSTREAM_SITES_PREVIEW=false`：模型/价格每 5 分钟自动同步，新建托管账号正常启用，原有待上线账号在同步时解除标记及自动停用。已核对分组 10、11 只绑定这批托管账号，启用时没有 API Key、调用记录或其他分组路由引用。绑定仍会真实创建上游 Key 和本地账号；预览测试请求使用 6556 和对应新分组。

各档位按实际价格及手动开关独立判断，不能再因运行于预览环境而统一停止调度。例如采购价 $0.045/张、分组上限 $0.04/张时，价格有效期内仍显示「超价暂停」。自动同步成功后更新 10 分钟的价格有效期；同步失败且自动价格过期时仍停止调度，也可手动同步重新核价；手动采购价不随自动价格过期。已有手动关闭的调度开关不被自动打开。

价格保护只覆盖对应的站点托管账号，按绑定的本地分组和模型执行。历史手工账号不会因为名称或地址相同而自动关联，也不会自动套用另一分组的上限。排查时必须核对托管账号 ID、本地分组、实际启用状态和使用记录；手工 `schedulable` 开关打开不代表请求能通过价格检查。旧账号的迁移另按用户要求安排。

允许预览调度不等于批准生产发布。用户确认上线后，仍须按 `ops/README.md` 发布已提交并推送、审阅过的完整版本。生产服务不设置预览变量，已有手动暂停账号不会被自动启用。

## 手动采购价与自动分组 Key

「上游模型」每行提供「填写采购价 / 修改采购价」，模型绑定列表也可直接修改同一模型的采购价。图片按 1K / 2K / 4K 填写 USD/张，空白档位保持暂停，0 是明确免费；也支持按次和 USD/百万 Token。Token 缓存/图片项留空按对应输入或输出单价计算，免费需要明确填 0。价格是实际支付的最终美元单价，不再乘上游倍率。保存后立即刷新该站点、该上游分组和模型的全部绑定策略，每次实际发送复查最新策略，继续执行本地价格上限、等价开关及手动启停。

手动采购价独立持久化，自动同步和暂时移除模型不会覆盖。恢复自动价格直接使用最近同步的数据；没有自动价格则提示填写。手动价格不受十分钟自动价格缓存期限影响，但已知下架的模型仍然不能调度。更换站点地址/账号身份时清除原身份的手动价格。

缺少读取 Key 时仅为 `/groups/available` 中的可用分组创建。先找已启用且可用的现有 Key，再用稳定的 `s2site-catalog-<site ID>-<group ID>` 名称恢复或创建；新 Key 保存在站点加密凭据中，重试和周期同步复用，不在 API 响应暴露。读取模型遇到服务错误不重复创建 Key；权限不足、Key 创建失败等只提示受影响分组。测试使用本地上游桩验证创建、复用、加密持久化、失败重试、手动价保存/同步保留/恢复及已排队请求读取新价。
