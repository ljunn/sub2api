# 上游站点与价格调度

后台「站点管理」支持 Sub2API、New API 和空凡。填写站点首页地址和后台登录凭据，保存后获取可用分组、模型和价格。登录凭据使用 AES-256-GCM 加密，密钥从持久化的 JWT 安装密钥通过带独立用途标识的 HMAC-SHA256 派生，不依赖未配置时会随机变化的 TOTP 密钥。列表与错误响应不返回密码、Token 或上游 Key。支持密码、Access Token、Refresh Token；需要验证码或二次验证的站点先在上游完成登录，再提供令牌。

备份时保留安装配置中的 JWT 密钥；预览与生产必须使用同一个已持久化的 JWT 密钥。轮换此密钥前需安排站点凭据迁移，直接更换会使旧站点凭据无法解密。

绑定选择「上游分组 + 模型 → 本地分组 + 模型别名」。托管账号名称统一为 `【站点】上游模型（上游站点分组）`，括号中不是本地分组；新建及同步时更新托管名称，历史非托管账号不变。采购单价上限自动读取本地分组、模型售价计算，不接受手工数值；绑定页面只配置档位启停。每个绑定自动创建一个独立上游 Key 和本地 API Key 账号。上游 Key 用绑定 UUID 命名，创建超时后重试先查找已有 Key。Sub2API Key 固定分组；New API Key 同时限制模型并关闭跨分组重试。本地托管账号的凭据、分组和模型映射由站点管理维护。

一个模型绑定对应一个账号，1K、2K、4K 是该账号内的独立价格档位。超价只排除对应档位；请求分辨率未知或为自动时要求所有分辨率均符合上限。上游价格下降后下一次成功同步自动恢复；本地调价由每次调度和实际发送前重新读取，自动暂停或恢复，手工暂停账号不会被价格恢复覆盖。

## 紧凑展示与实际调度状态

站点绑定改成每个模型一行的表格；1K、2K、4K 采购价及是否可调度（✓/×）同一行展示，悬浮查看本站售价、采购上限和阻断原因，完整配置仍在「定价 / 启停」。上游分组与本地分组分列，避免名称混淆。

账号管理通过 `site_scheduling` 返回实时评估结果，读取当前分组定价而非账号中保存的旧上限。站点托管账号显示「参与调度」「部分可调度」或「停止调度」，每档有超价、过期、未知、停用或等待上线原因，不再显示含糊的「按分组售价判断」。状态栏和调度栏使用相同结果；手动调度开关不再被展示成价格检查通过。

全部档位不符合时实际请求会被价格门禁排除，调度和每次向上游发送前均复查；某档不符合只停止该档。自动价格阻断不覆盖管理员手动开关，从而允许降价后自动恢复，手动停用仍保持停用。页面是普通分组价的当前判断，实际请求还检查用户专属倍率和运行时限流。没有给历史账号自动添加托管关系。

## 自动采购上限

托管绑定的实际扣费也固定使用本地模型别名，不随上游模型改名或响应中的模型名改变。本站售价复用实际计费解析链（本地分组模型价卡 → 渠道模型价 → 目录/内置默认价），并计入分组倍率。图片使用分辨率定价及图片独立倍率，token 使用高峰和渠道分时倍率。开启分组利润保护时：`上限 = 本站售价 × (1 − 最低利润率 − 安全余量)`；关闭时上限等于售价，仍避免已知单价亏损。

页面显示普通用户的分组售价。请求调度还会读取用户专属倍率；图片独立倍率仍按现有计费规则处理。本地价卡修改后无须重新绑定或等待上游同步。若请求持有修改前的分组快照，使用新旧售价较低者比较。账号保存的上限仅用于展示，不作为实际发送的价格依据；无法读取本地价格时停止该绑定的调度。

上游图片为固定单价时展开成 1K / 2K / 4K，与本站三档分别比较。上游上下文采用最高采购价，本地上下文采用最低售价，避免未识别上下文档位造成亏损。无法覆盖的计费项目（例如没有对应本站单价的独立音频 token）暂停该档位；应在本站配置对应计费能力后接入。

## 同步与价格口径

- 后台每分钟检查到期任务，每次同步后安排 5 分钟后的下一次同步；页面支持「立即同步」。成功价格有效期 10 分钟，短暂同步失败保留未过期价格，过期后停止调度。
- 价格包含上游个人/分组倍率。Sub2API 图片独立倍率、上下文阶梯、分时/高峰、最高推理倍率按已公开字段处理；上下文与分时价格采用最高单价作为保守上限。
- USD/次、USD/张、USD/百万 token 分开比较。输入、输出、缓存和其他公开成本分量分别从本地计费价格计算上限，未覆盖项目不视为免费。
- New API 支持固定按次价格、token 倍率，以及可安全归约的非负线性计费表达式（条件分支取各分量最高值）。复杂任务插件、非线性规则或不完整价格显示不可核价并暂停调度。额外服务档位（priority/fast/flex 等）尚未单独核价，托管账号不会承接这类请求。
- Sub2API 需要上游启用模型广场；无法获得完整价格时明确提示。模型改名或下架不会自动猜测替换关系，需要重新绑定到本地别名。
- 站点目录、绑定账号价格策略和调度缓存失效事件在一个 PostgreSQL 事务中发布。请求调度及每次实际发送（含重试）均检查价格；已付费结果的 GET 下载不受新涨价影响。
- 保留最近 100 条价格变化。解除绑定删除本地托管账号，上游 Key 保留；删除站点须先解除全部绑定。

五分钟轮询无法感知两次扫描之间的即时涨价；本功能依赖上游发布的价格，不自动推算充值折扣或汇率。

## 预览与发布

6556 仍复用生产 PostgreSQL、JWT、现有管理员及业务数据，Redis 保持独立 DB 14。预览服务必须设置 `UPSTREAM_SITES_PREVIEW=true`：停用自动价格同步任务（余额扫描和系统邮件提醒仍运行），新建托管账号以停用状态保存，避免旧生产程序在没有新价格保护的情况下调度它们。预览可以手动同步和绑定；绑定会真实创建上游 Key 和本地账号。

站点绑定会明确提示待上线的托管账号已停用、不参与调度。各档位仍独立显示超价、过期、未知或手工停用原因，不能让「预览待上线」覆盖价格拦截；只有价格检查通过的待上线档位显示「预览待上线」。例如采购价 $0.045/张、分组上限 $0.04/张时，价格有效期内应显示「超价暂停」。预览不自动续期价格，超过 10 分钟显示「价格已过期」，可手动同步重新核价。

价格保护只覆盖对应的站点托管账号，按绑定的本地分组和模型执行。历史手工账号不会因为名称或地址相同而自动关联，也不会自动套用另一分组的上限。排查时必须核对托管账号 ID、本地分组、实际启用状态和使用记录；手工 `schedulable` 开关打开不代表请求能通过价格检查。旧账号的迁移另按用户要求安排。

用户确认上线后，按 `ops/README.md` 发布已提交并推送的版本。生产服务不设置预览变量，首次同步后会激活标记为待发布的托管账号。已有手动暂停账号不会被自动启用。

## 验证

服务测试使用本地 HTTP 上游桩，覆盖密码加密、令牌轮换、Key 超时恢复、价格上涨/回落、过期与逐次重试检查；调度测试同时覆盖普通与高级调度器、独立分辨率过滤。仓库集成测试用专用 PostgreSQL/Redis 容器验证事务、迁移、锁与缓存失效，不向生产库写测试数据。前端测试覆盖只读自动上限、定价读取失败、分辨率独立启停、模型别名、凭据不回填及同步错误显示。

所有待发布源码、测试和文档须统一提交、推送并构建，余额、空凡和价格调度功能一起更新 6556。不得跳过其他未提交改动或使用已移除的 `--committed-head` 选项；完整版本审阅确认后才可整体上线，具体规则见 `AGENTS.md` 与 `ops/README.md`。
