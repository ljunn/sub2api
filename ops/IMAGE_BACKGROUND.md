# 渠道透明背景能力

账号管理的 OpenAI、Grok 账号创建与编辑弹窗增加「支持透明背景」。站点托管账号同样可编辑。取消勾选后，该账号不参与明确要求透明背景的图片请求；重新勾选即可恢复。已有账号未设置时保持原有调度行为。

设置存储在账号 `extra.images_transparent_background_supported`，仅接受 JSON 布尔值。无需数据库迁移。旧客户端更新其他字段时省略此键，不会清除已保存的 `false`；站点价格同步保留该设置。

## 请求识别与调度

- OpenAI/Grok 图片生成和编辑：读取 JSON 或 multipart 的 `background=transparent`。
- Responses HTTP 与 WebSocket：读取 `tools` 中 `type=image_generation` 的 `background=transparent`。
- `background=opaque`、`auto`、未指定背景的请求沿用正常调度。不根据提示词、PNG/WebP 格式或参考图的 alpha 通道推断透明背景。
- 过滤覆盖首次选账号、粘性账号、缓存快照、数据库复核、失败重试及换渠道。被能力过滤的账号不消耗失败切换次数。
- 内部转发也执行发送前检查，防止绕过调度。没有支持透明背景的可用账号时返回无可用渠道错误，不降级成不透明背景，也不向已声明不支持的账号试发请求。
- 已建立的 WebSocket 会话若在后续消息新增透明背景要求，而绑定账号不支持，则拒绝该消息并关闭连接，提示发起新请求；新连接重新选账号。

此开关是管理员声明的渠道能力，不执行上游探测，不改变请求的背景参数、模型、采购价格或视频调度。

## 验证与审阅

新增单元回归覆盖 OpenAI/Grok 图片生成、JSON/multipart 编辑、多账号故障切换、全部不支持、普通背景、`auto`、未指定背景、Responses 工具识别、两种调度器的粘性账号、缓存中的 `false`、托管账号保存及站点同步。前端验证新建/编辑的默认值、恢复保存值、关闭与重新开启、其他 Extra 字段保留。

测试使用模拟账号与上游，不向共享生产数据库写入测试夹具，不提交收费的真实生成任务。提交、推送并构建完整版本后更新 6556；生产仍须用户审阅并明确确认后发布。
