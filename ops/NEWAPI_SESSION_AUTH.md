# New API 登录会话复用

2026-09-21 实查参分站点：`/api/user/login` 返回 HTTP 409，结构化错误码
为 `AUTH_SESSION_LIMIT`。已有会话的刷新请求使用配置 IP 地址作为 Origin，
被 `/api/user/auth/refresh` 以 HTTP 403、`AUTH_ORIGIN_FORBIDDEN` 拒绝。
上游 `/api/status` 公布的 `server_address` 为 `https://ztyunjuan.com`，
该来源能正常刷新。旧逻辑把刷新 403 当作登录失效，使用密码创建新会话，
累积至上游会话数量上限；有效 Access Token 期间的扫描本来就会复用登录。

修复后，仅针对明确的 New API `AUTH_ORIGIN_FORBIDDEN`，读取其公开状态接口
公布的 HTTPS 官网来源，重试刷新同一个会话一次。所有请求继续发送到管理员
配置的接口地址，不把密码、Cookie 或 Token 转发到公布的域名。无有效官网来源、
重试仍受拒绝、其他 403、刷新竞争或限流都直接报告错误，不退回密码登录。
真正的 401 失效及旧站点未实现刷新接口时，保留密码登录兼容。

已知认证错误码给出明确中文原因；未知响应继续使用通用提示，避免把上游正文、
凭据或内部诊断泄露到页面。目录读取失败时仍保存成功轮换的认证信息；之后扫描
继续复用它。并发扫描和预览/生产共享现有 PostgreSQL 站点锁，避免同时轮换令牌。

本次在现有站点锁内使用保存的刷新令牌成功续期，确认返回的会话 ID 与原会话
一致，并保存加密后的新令牌。随后参分同步恢复 `connected`，读取 46 个模型。
没有新建登录、撤销其他设备会话或修改上游会话限额。数据修复使用现有业务账号，
自动化回归仅使用本地 HTTP 桩和内存仓库。

回归覆盖 IP 来源拒绝后的官网来源刷新、目录失败时持久化轮换令牌、连续扫描
零密码登录、权限/来源/竞争/限流错误不创建会话，以及错误提示脱敏。
预览更新前的旧进程仍有旧逻辑；完整构建并更新 6556 后才会自动按新逻辑刷新。
