# 站点托管账号的模型独立优先级

这项功能在 Sub2API 内执行。只对站点绑定生成的托管账号计算自动优先级，候选池按本地分组、平台、模型分别比较，图片还区分 1K / 2K / 4K / 自动尺寸。不修改账号保存的手动优先级或调度开关，不做末尾淘汰，所有符合现有健康、价格和并发规则的备用账号都保留。

## 评分

```text
R = (成功转发数 + 1) / (转发尝试数 + 2)
T = 0.6 × 成功耗时 P50 + 0.4 × 成功耗时 P90
P = 采购单价 / 对应本地实际售价
S = 100 × R² × T0/(T0+T) × 0.5/(0.5+P)
```

同一账号、同一模型、同一规格使用最近 1 小时最多 200 次实际转发结果。图片使用从发送上游到完整出图返回的耗时；文本优先使用首 Token 时间，无首 Token 统计时使用完整耗时。只有成功请求进入耗时分位数，快速报错不会提升速度分。图片的 `T0=30` 秒，文本的 `T0=3` 秒；图片无成功耗时暂估 120 秒，文本暂估 10 秒。无样本的平滑成功率为 50%，页面显示样本不足。

价格复用现有站点定价与售价解析：同币种、同计费单位、同规格比较，先通过现有价格准入。Token 价格按各计费项目采购/售价比例的最大值计算，不将每张、每次、每百万 Token 单价相加；自动图片尺寸采用所需档位的保守最大比例。免费项目仅在采购与售价均为零时记为零比例。空凡使用实际采购的分辨率，并继续执行它原有的采购规格与本地计费规格双重价格检查。

## 优先级与统计边界

- 各独立候选池分数最高的账号为 `200`；同分以账号 ID 决定首位。
- 其他账号为 `1000 + round(2000 × log10(100/S))`，范围 `1000～25000`，分数越高数值越小。
- 现有会话粘性、模型能力、并发获取、限流、熔断、价格检查与失败切换继续生效。高级调度按上述优先级排列托管账号，并保留超出 Top-K 的托管备用；混合池保留独立账号的原相对顺序。
- 统计一轮账号转发结果，跨账号切换分别记录；协议转换嵌套只记录一次。尚未实际发送上游的本地错误、客户端主动断开、明确参数错误不计为账号失败；可换渠道的上游错误（包括 retry-later HTTP 400）计为失败。
- 评分按请求临时计算在账号副本上，避免一个规格的分数覆盖另一规格，也避免预览把优先级写入共用生产数据库。统计保存在当前进程内存，重启后重新积累，预览与生产分别学习，不从历史使用日志回填。
- 账号列表的优先级列展示各可用规格的计算结果，展开可查看综合分、平滑成功率、样本数、耗时与成本比例。后台展示的同池排名缓存 5 秒，实际请求不使用此展示缓存。
